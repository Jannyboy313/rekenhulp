# Plan: v4 tablet layouts and Design V3

Spec: `docs/superpowers/specs/2026-11-14-tablet-design.md` ("the spec" below; "main spec" is
`2026-10-05-rekenhulp-design.md`). Pixel reference while it exists: `design-handoff/` (local).

Rules for every task: tests first, then code; `npm test` and `npm run check`; `npx prettier
--check` on the touched files; `git diff` each file before `git add`; one commit per task.
Documentation of spec §13 changes in the task that changes the behaviour. After each bundle: reread
its diff against the spec, run `npm run screenshots` and look at the PNGs of the touched screens,
give a short status.

`main` stays deployable: until a screen is converted it keeps the phone column on a tablet.

### Task 6: physical keyboard (spec §6)

- Files: new `lib/physicalKeys.ts` + test, `KeypadAnswer.svelte`, `Keypad.svelte`,
  `QuestionView.svelte`, `PlayScreen.svelte`, their tests, main spec §2 and §6, spec §6 (wording
  fix: `PlayScreen` owns Enter for **Verder**, not `Feedback`; done with this plan's commit).
- `keyFor(key: string, available: readonly KeypadKey[], hasOk: boolean): KeypadKey | 'ok' | null`.
- `choiceFor(key: string, kind: 'boolean' | 'choice', count: number): number | null` (index into
  the buttons; Ja/Nee order is Nee, Ja).
- `KeypadAnswer`: `svelte:window onkeydown`. Ignores Ctrl/Alt/Meta, `locked`, and Enter with
  `event.repeat`. Passes the keys of the keypad on screen (the kladblok keypad while a cell is
  active). A mapped key calls `preventDefault()` and then `handleKey` or `submit`. On a keypad key
  that has focus, Enter is OK (the default is prevented); on any other focused button Enter and
  Space stay native.
- `Keypad`: prop `pressed?: KeypadKey | 'ok' | null`, drawn like `:active`; `KeypadAnswer` clears
  it after 100 ms.
- `QuestionView`: the same listener for Ja/Nee and choice through `choiceFor`.
- `PlayScreen`: Enter in the wrong state calls `handleNext` when the focus is not on a button and
  no lesson is open; Escape closes an open lesson.

| `keyFor` key   | Keypad        | Expected      |
| -------------- | ------------- | ------------- |
| `5`            | number        | `5`           |
| `,` and `.`    | number        | `,`           |
| `-`            | number        | `-`           |
| `c`            | number        | null          |
| `c`, `C`       | baseDigits    | `C`           |
| `g`            | baseDigits    | null          |
| `x`            | roman         | `X`           |
| `x`, `*`       | expression    | `×`           |
| `*`            | number        | null          |
| `/`            | fraction      | `/` (breuk)   |
| `/`            | expression    | `:`           |
| `/`            | kladblok      | `/` (breuk)   |
| `:`            | kladblok      | `:`           |
| `:`            | fraction      | null          |
| `(`, `)`       | expression    | same key      |
| `^`            | factorization | `^`           |
| `=`            | kladblok      | `=`           |
| space          | kladblok      | spatie        |
| space          | number        | null          |
| `Backspace`    | any           | `backspace`   |
| `Enter`        | number        | `ok`          |
| `Enter`        | kladblok      | null (no OK)  |
| `Tab`, `Dead`  | any           | null          |

| `choiceFor` key | Kind, count | Expected |
| --------------- | ----------- | -------- |
| `n`, `N`        | boolean     | 0        |
| `j`             | boolean     | 1        |
| `1`             | boolean     | null     |
| `1` … `4`       | choice, 4   | 0 … 3    |
| `5`, `0`        | choice, 4   | null     |
| `j`             | choice, 4   | null     |

| Component case                                        | Expected                                   |
| ----------------------------------------------------- | ------------------------------------------ |
| type `1` `2`, Enter on a number step                  | `onanswer` with `12`                       |
| Enter with empty input                                | nothing                                    |
| Ctrl + `5`                                            | nothing, default not prevented             |
| a key in the correct state                            | nothing                                    |
| kladblok cell active, type `8`                        | goes to the cell, not the field            |
| a keypad digit has focus, Enter                       | submits, the digit is not typed again      |

| `j` on a Ja/Nee step                                  | `onanswer` with Ja                         |
| wrong state, Enter with the focus on `body`           | next question                              |
| wrong state, lesson open, Enter                       | nothing                                    |
| a typed key                                           | its on-screen key has `pressed` for 100 ms |

## Bundle D — play screen on tablet (spec §4)

### Task 10: sizes as tokens, and portrait (spec §4.1, §4.4)

- Files: `app.css`, `PlayScreen.svelte`, `QuestionView.svelte`, `KeypadAnswer.svelte`,
  `Keypad.svelte`, `Scratchpad.svelte`, `Feedback.svelte`.
- The table of spec §4.1 becomes one block of custom properties in `app.css` (`--play-key-height`,
  `--play-key-gap`, `--play-keypad-height`, `--play-key-label`, `--play-field-height`,
  `--play-cell-height`, `--play-cell-gap`, `--play-sum-large` / `-medium` / `-small`,
  `--play-text`, `--play-yesno`, `--play-choice-text`, the wrong-state sizes, `--play-meta`,

  the phone values do not change (checked on the phone PNGs).
- Column: `[data-layout^='tablet'] #app` loses its `max-width`; every screen's root gets
  `max-width: var(--column, 30rem)` and `margin-inline: auto`, so a screen that is not converted
  keeps the phone column. The play screen sets `--column: 560px` in `tablet-portrait`.
- Portrait: Ja/Nee 160 high, multiple choice 2 × 2 of 104, the tray with padding 12 and radius 20.
- Check on the PNGs: the tray is as high as the keypad in portrait (5 × 60 + 4 gaps + 24); if
  not, set the tray gap so that it is (the phone does this with its 19 px margin).
- CSS only; no new unit tests. Screenshots at 800 × 1280 against
  `design-handoff/screens/tablet-portrait/`.

### Task 11: landscape with a keypad, and compact (spec §4.2)
