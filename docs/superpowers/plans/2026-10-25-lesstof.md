# Lesstof framework + Tafels — plan

Spec: §3.1, §3.2, §3.7 (incl. §3.7.1 Tafels). TDD, one commit per task. Scope: the framework and
the Tafels lesson only; the other sets follow one at a time in later sessions.

## Decisions

- Content is typed data in `lib/lessons/`, rendered with `MathText`. No markdown, no new dependency.
- A lesson belongs to a set by `setId`; its topics are its own (not the generator topics).
- Sets without a lesson are hidden in the Lesstof tab and get no Lesstof button.
- Active tab is `App.svelte` state (in memory only, nothing persisted).
- Not doing: read marks, search, next/previous, lessons during play, images.

## Task 2 — content checker (`lib/lessons/chains.ts`)

Files: `lib/lessons/chains.ts`, `lib/lessons/chains.test.ts`

`chainHolds(line: string): boolean` splits on ` = `, parses every side with `lib/expr`
`parse`, evaluates with `evaluate` and compares with `rational.equals`. Returns `false` for an
unparsable side or a line without ` = `. Uses the SLOT-free form only.

| Input | Expected |
| --- | --- |
| `13 × 7 = 10 × 7 + 3 × 7 = 70 + 21 = 91` | true |
| `84 : 6 = 60 : 6 + 24 : 6 = 14` | true |
| `7 × 8 = 7 × 7 + 7 = 56` | true |
| `13 × 7 = 90` | false |
| `13 × 7` (no equality) | false |
| `13 × = 91` (unparsable) | false |
| `100 − 10 − 5 = 85` (left to right) | true |

## Task 3 — Tafels lesson content (`lib/lessons/tables.ts`)

Files: `lib/lessons/tables.ts`, `lib/lessons/tables.test.ts`; register in `index.ts`.

Topics as in spec §3.7.1 (`tricks`, `neighbours`, `splitting`, `division`, `missingFactor`).
Dutch text, Dutch notation, `×` and `:`. Every `worked` line is checked by `chainHolds`; a unit
test walks all blocks of all lessons.

Worked examples (all verified by hand):

| Topic | Lines |
| --- | --- |
| tricks | `4 × 7 = 2 × 7 × 2 = 14 × 2 = 28`; `5 × 8 = 10 × 8 : 2 = 80 : 2 = 40`; `9 × 7 = 10 × 7 − 7 = 70 − 7 = 63`; `11 × 6 = 66`; `11 × 14 = 10 × 14 + 14 = 154` |
| neighbours | `7 × 8 = 7 × 7 + 7 = 49 + 7 = 56`; `8 × 7 = 8 × 8 − 8 = 64 − 8 = 56`; `6 × 7 = 6 × 6 + 6 = 42` |
| splitting | `13 × 7 = 10 × 7 + 3 × 7 = 70 + 21 = 91`; `14 × 6 = 10 × 6 + 4 × 6 = 60 + 24 = 84`; `15 × 8 = 10 × 8 + 5 × 8 = 80 + 40 = 120`; `13 × 14 = 13 × 10 + 13 × 4 = 130 + 52 = 182` |
| division | `91 : 7 = 13` (because `13 × 7 = 91`); `84 : 6 = 60 : 6 + 24 : 6 = 10 + 4 = 14` |
| missingFactor | `91 : 7 = 13`; `126 : 14 = 9` (check: `14 × 9 = 126`) |

Plus a `table` for the 9-trick (tens digit one lower, digits add up to 9) and a `tip` per topic
where it earns its place. Extra tests: no ASCII `*`, ` x ` or `/` as operator in any text; no
literal `?` inside a `worked` line.

Review point for the user: the wording and the choice of methods are didactic choices; read the
texts before this task is committed as final.

## Task 6 — wiring, back guard, setup link (`App.svelte`, `SetupScreen.svelte`)

- `Screen` gains `{ name: 'lessonTopics'; set; from: 'sets' | 'setup' }` and
  `{ name: 'lesson'; set; topic; from }`. `tab` state in `App.svelte`.
- `SetupScreen` gains optional `onlesson`; the button **Lesstof** renders only when it is passed
  (App passes it when `lessonFor(set)` exists). Layout decided here: secondary button above
  Start, test on the phone.
- Back guard: the `$effect` arms on every non-`sets` screen, but a `popstate` consumes the entry,
  and `lesson → lessonTopics` stays non-`sets`, so the effect does not re-run. `handlePopState`
  must call `backGuard.arm()` after a step that stays off `sets` (same as the `playing` branch).
  Terug for `lessonTopics`: `from === 'setup'` → setup of that set, else `sets` (tab stays).

| Test (component/integration) | Expected |
| --- | --- |
| Lesstof tab → Tafels → topic → Terug → Terug | back on `sets`, Lesstof tab still active |
| setup of Tafels → Lesstof → Terug | setup, count and table choice unchanged |
| setup of a set without a lesson | no Lesstof button |
| system back (popstate) on `lesson` | `lessonTopics`, guard re-armed (a second back moves on) |
| system back on `lessonTopics` | `sets` / `setup` per origin |
