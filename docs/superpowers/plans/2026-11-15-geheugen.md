## Task 1 — record, mapping and the volatile memory

Files: `src/lib/memory.ts` (new), `src/lib/memory.test.ts` (new).

```ts
export type RecordSource = 'set' | 'test' | 'lesson';
export interface PracticeRecord { topic: string; correct: boolean; at: number; source: RecordSource }
export interface Memory {
  add(records: readonly PracticeRecord[]): Promise<void>;
  all(): Promise<PracticeRecord[]>;
  clear(): Promise<void>;
}
export function toPracticeRecords(
  records: readonly QuestionRecord[], source: RecordSource, at: number,
): PracticeRecord[];
export function createVolatileMemory(): Memory;
```

`toPracticeRecords` uses `isCorrect` from `lib/results.ts`. `all()` returns a copy.

| Case (`toPracticeRecords`)                           | Expected                                         |
| ---------------------------------------------------- | ------------------------------------------------ |
| no records                                           | `[]`                                             |
| one step, correct                                    | `{ topic, correct: true, at, source }`           |
| one step, wrong                                      | `correct: false`                                 |
| two steps, second wrong                              | `correct: false`                                 |
| two steps, only the first answered (stopped)         | `correct: false` (as `isCorrect`)                |
| three records, source `test`, `at` 1000              | three records in order, each `test` and `1000`   |

| Case (volatile memory)                    | Expected                                 |
| ----------------------------------------- | ---------------------------------------- |
| `all()` on a new memory                   | `[]`                                     |
| `add([a, b])`, `add([c])`, `all()`        | `[a, b, c]`                              |
| `add([])`                                 | `all()` unchanged                        |
| `clear()` after adds                      | `all()` is `[]`                          |
| mutating the array returned by `all()`    | a next `all()` is unchanged              |
| two memories                              | do not share records                     |

## Task 2 — IndexedDB memory and the fallback

Files: `src/lib/memory.ts`, `src/lib/memory.test.ts`, `package.json` + lockfile (dev dependency
`fake-indexeddb`).

```ts
export function openMemory(factory: IDBFactory | undefined, onFirstAdd?: () => void): Memory;
```

- Database `rekenhulp`, version 1, store `records` (`autoIncrement: true`), no indexes.
- Opened on the first call; the promise of the backend (IndexedDB-backed, or volatile after a
  failed open) is cached. `versionchange` closes the connection and drops the cache.
- A missing factory, a throwing `open`, an `error` or a `blocked` open: volatile for the rest of
  the run, `console.error` once.
- `add`: one `readwrite` transaction, resolves on `complete`, rejects on `error`/`abort`.
  `add([])` opens nothing. `onFirstAdd` fires once, after the first successful non-empty add to
  IndexedDB, never for the volatile fallback.
- The test table of task 1 becomes `describe.each` over both variants; each IndexedDB case gets
  a fresh `new IDBFactory()` from `fake-indexeddb`.

| Case (`openMemory`)                                              | Expected                                        |
| ---------------------------------------------------------------- | ----------------------------------------------- |
| the six volatile cases, on a fresh factory                       | same results                                    |
| `add` on one `openMemory(factory)`, `all()` on a second          | the records are there                           |
| `clear()` on one, `all()` on a second                            | `[]`                                            |
| `openMemory(undefined)`: add, all                                | works, volatile                                 |
| a factory whose `open` throws: add, all                          | works, volatile; `console.error` once for both  |
| a factory whose `open` request fails                             | works, volatile                                 |
| `onFirstAdd` with `add([])`, `add([a])`, `add([b])`              | called once, after the second call resolves     |
| `onFirstAdd` with `openMemory(undefined, spy)` and an add        | not called                                      |
| a `versionchange` (a second open with version 2), then `all()`   | resolves (reopened or volatile), does not hang  |

Commit: `Added the IndexedDB memory with a volatile fallback`

## Task 3 — saving a session

Files: `src/App.svelte`, `src/App.test.ts` (append; the file exists), `src/main.ts`,
`e2e/offline.spec.ts`.

- `App` prop `memory?: Memory`, default `createVolatileMemory()` (created once, `untrack`).
- `function save(origin: Origin, records: QuestionRecord[])`: `memory.add(toPracticeRecords(
  records, origin.kind, Date.now()))`, not awaited, a rejection goes to `console.error`. Called
  from `finishSession` and `finishTest`. `Origin['kind']` is already a `RecordSource`.
- `main.ts`: `openMemory(globalThis.indexedDB, () => void navigator.storage?.persist?.()
  .catch(() => {}))`, passed as the `memory` prop.

| Case (`App.test.ts`, a volatile memory passed as prop)       | Expected                                           |
| ------------------------------------------------------------ | -------------------------------------------------- |
| a set session played to the end                              | one record per exercise, source `set`              |
| a wrong first attempt, then the repeat answered correctly    | one record for that exercise, `correct: false`     |
| a session stopped after two answers                          | two records                                        |
| a session stopped at once                                    | no records                                         |
| Fouten oefenen after a set session                           | its records added too, source `set`                |
| Oefen 5 sommen from the fixture lesson                       | source `lesson`                                    |
| a test stopped after one answer                              | one record, source `test`                          |
| `vi.setSystemTime` before the session ends                   | every record has that `at`                         |
| a memory whose `add` rejects                                 | the results screen shows; `console.error` called   |
| no `memory` prop                                             | the session ends as before (existing tests pass)   |

Smoke (`e2e/offline.spec.ts`, a second test): play a Tafels session online until Stop after one
answer, then count the `records` store with `page.evaluate` → 1; reload → still 1. Run
`npm run smoke` before the push (`main.ts` changes).
