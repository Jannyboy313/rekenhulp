# Kladblok Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A kladblok (scratchpad) while playing: 4 cells in a 2×2 grid above the prompt. The user taps a cell and types a number on the standard number keypad. OK turns into **Volgende**. The notes last one question and are hidden for tables and Ja/Nee.

**Architecture:**

- **Pure model in `lib/scratchpad.ts`.** Cell count, the empty notes, the Volgende order, typing into one cell (the number reducer), when the kladblok is shown, and the short-screen media query. It also declares `ScratchpadInput`, the small interface through which `KeypadAnswer` hands the keypad to the kladblok.
- **State ownership follows lifetime.** `PlayScreen` owns the notes, because they outlive a step: they survive the feedback between the two steps of a question and are reset when the question changes. `QuestionView` is keyed per step, so it owns the active cell (`activeNote`), and every step starts with the answer field active. `QuestionView` binds the notes (`bind:notes`).
- **Keypad routing in `KeypadAnswer`.** It already owns the keypad. With a `scratch` prop whose `active` is true, it shows the number keys, sends keys to the cell and labels OK **Volgende**. A transparent button covers the answer field while a cell is active. One tap on it, also on a fraction slot, hands the keypad back to the answer.
- **Short screens.** `QuestionView` reads `matchMedia('(max-height: 759px)')` once per step and then shows and cycles through only the top row (2 cells). Keeping this in JavaScript, and not in a CSS media query, makes sure Volgende never moves to a hidden cell.

**Tech Stack:** Svelte 5 (runes, `$bindable`), TypeScript (strict, `noUncheckedIndexedAccess`), Vitest + @testing-library/svelte (jsdom). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-05-rekenhulp-design.md`. Read §3.3, §3.6, §6 and §11.15 before starting.

## Scope

| Spec section | What is built |
|---|---|
| §3.6 layout | 2×2 cells of 48 px between header and prompt; fixed size, clipped, never wrapped |
| §3.6 short screens | Below 760 px viewport height only the top row (2 cells) |
| §3.6 when shown | Not for topic `tables`, not for Ja/Nee steps |
| §3.6 focus | Tap a cell, tap the answer field (or a slot) to go back; `--primary` border on the active field; new step starts on the answer |
| §3.6 while a cell is active | Number keys only; number reducer; OK → **Volgende**, always enabled, next cell then back to the answer |
| §3.6 lifetime | Notes kept across the steps of a question, reset at the next question, not shown in feedback or results |
| §3.6 accessibility | Cells are buttons `Kladblok vak 1: 900` / `leeg` with `aria-pressed`; group labelled `Kladblok` |
| §3.6 room | Keypad keys 3 rem (48 px) instead of 3.5 rem |

**Out of scope:** copying a note into the answer, clearing the kladblok, operators in notes, persistence of any kind.

## Domain notes for the implementer

- **Notes are raw number input strings**, exactly like the number answer field: digits, at most one `,`, an optional leading ASCII `-`. They are typed with `applyKey` (via `INPUT_MODELS.number.apply`) and shown with `formatInput`, which only turns `-` into `−` (U+2212). There are no thousands separators while typing.
- **Glyphs used in this plan:** `−` U+2212, `⌫` U+232B, `…` U+2026, `×` U+00D7. All are visible characters; type them as shown.
- **`press` vs `onclick`.** Cells and the answer-field overlay use the `press` action (`src/components/press.ts`): they act on `pointerdown` and ignore the click that follows. OK/Volgende stays on `onclick`, like OK today. In tests, `fireEvent.click` fires a click with `detail === 0`, which `press` treats as keyboard activation, so `fireEvent.click` works for every button.
- **Whitespace in Svelte markup matters** inside the answer `<output>` (CLAUDE.md, "Svelte pitfalls"). Task 4 re-indents that block by two spaces. Every line break in it is inside a tag or inside a `{@render …(` argument list, so re-indenting is safe. Do **not** add or remove line breaks between tags.
- **The short-screen threshold** comes from a height estimate. With 48 px keys, a fraction step with a two-line prompt needs: padding 32 + header 48 + gap 16 + kladblok 104 + 4 gaps 64 + prompt 96 + field 96 + error ≈ 4 + keypad 272 = 732 px. On notched iPhones, the safe areas add about 60 px. Below 760 px only one row (48 px + 8 px gap less) is shown. Task 6 checks this on a real phone.
- **jsdom has no `matchMedia`.** `QuestionView` checks `typeof matchMedia === 'function'` first. Tests stub it with `vi.stubGlobal`.

Create `src/lib/scratchpad.ts`:

```ts
import { INPUT_MODELS, type KeyDef } from './inputModels';
import type { KeypadKey } from './keypadInput';
import type { AnswerKind, Topic } from './types';

/** Kladblok cells in a 2×2 grid, in reading order (spec §3.6). */
export const NOTE_COUNT = 4;

/** Short screens show only the top row, so the keypad stays on screen (spec §3.6). */
export const SHORT_NOTE_COUNT = 2;

/** Viewports lower than 760 px; see the height estimate in the kladblok plan. */
export const SHORT_SCREEN_QUERY = '(max-height: 759px)';

export const EMPTY_NOTES: readonly string[] = Object.freeze(Array<string>(NOTE_COUNT).fill(''));

/** The kladblok holds numbers only and types them on the standard number keypad. */
export const NOTE_KEYS: readonly KeyDef[] = INPUT_MODELS.number.keys;

/** The cell after `index` for Volgende, or null for the answer field after the last one. */
export function nextNote(index: number, count: number): number | null {
  return index + 1 < count ? index + 1 : null;
}

/** New notes with one key typed into cell `index`, using the number reducer. */
export function applyNoteKey(
  notes: readonly string[],
  index: number,
  key: KeypadKey,
): readonly string[] {
  return notes.map((note, i) => (i === index ? INPUT_MODELS.number.apply(note, key) : note));
}

/** Tables are practised from memory, and Ja/Nee steps have no keypad (spec §3.6). */
export function showsScratchpad(topic: Topic, kind: AnswerKind): boolean {
  return topic !== 'tables' && kind !== 'boolean';
}

/** How KeypadAnswer hands the keypad to the kladblok. */
export interface ScratchpadInput {
  /** A cell is active: the keypad types there and OK is Volgende. */
  active: boolean;
  onkey(key: KeypadKey): void;
  /** Volgende: the next cell, or back to the answer field after the last one. */
  onnext(): void;
  /** The answer field was tapped while a cell was active. */
  onfocusanswer(): void;
}
```

<script lang="ts">
  import { INPUT_MODELS } from '../lib/inputModels';
  import type { KeypadKey } from '../lib/keypadInput';
  import {
    applyNoteKey,
    EMPTY_NOTES,
    nextNote,
    NOTE_COUNT,
    SHORT_NOTE_COUNT,
    SHORT_SCREEN_QUERY,
    type ScratchpadInput,
  } from '../lib/scratchpad';
  import { NO, YES } from '../lib/steps';
  import type { CheckResult, Step } from '../lib/types';
  import KeypadAnswer from './KeypadAnswer.svelte';
  import MathText from './MathText.svelte';
  import Scratchpad from './Scratchpad.svelte';

  interface Props {
    step: Step;
    /** Whether this step shows the kladblok; PlayScreen decides per question (spec §3.6). */
    scratchpad?: boolean;
    /** The kladblok notes. PlayScreen binds them, so they outlive this step. */
    notes?: readonly string[];
    onanswer: (input: string, result: CheckResult) => void;
  }

  let { step, scratchpad = false, notes = $bindable(EMPTY_NOTES), onanswer }: Props = $props();

  // Short screens show only the top row (spec §3.6). Read once per step: the app is portrait
  // only. jsdom has no matchMedia.
  const noteCount =
    typeof matchMedia === 'function' && matchMedia(SHORT_SCREEN_QUERY).matches
      ? SHORT_NOTE_COUNT
      : NOTE_COUNT;

  // This view is keyed per step, so every step starts with the answer field active.
  let activeNote = $state<number | null>(null);

  const scratch: ScratchpadInput | undefined = $derived(
    scratchpad
      ? {
          active: activeNote !== null,
          onkey: typeNote,
          onnext: nextCell,
          onfocusanswer: () => (activeNote = null),
        }
      : undefined,
  );

  function typeNote(key: KeypadKey) {
    if (activeNote !== null) notes = applyNoteKey(notes, activeNote, key);
  }

  function nextCell() {
    if (activeNote !== null) activeNote = nextNote(activeNote, noteCount);
  }

  // Guards against a double tap submitting twice before the feedback replaces this view.
  let answered = false;

  function answer(input: string) {
    if (answered) return;
    answered = true;
    onanswer(input, step.check(input));
  }
</script>

<div class="question">

    <Scratchpad
      notes={notes.slice(0, noteCount)}
      active={activeNote}
      onselect={(index) => (activeNote = index)}
