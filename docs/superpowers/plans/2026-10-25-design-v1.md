# Design V1 redesign — plan

Spec: `docs/superpowers/specs/2026-10-05-rekenhulp-design.md` (updated in 74d7520; §2, §3.1–§3.6, §6).
Brief: the "Design V1: implementation brief" from the user. The canvas artboards could not be read
by the agent, so all sizes come from the brief. If an artboard differs, the artboard wins; tell the user.

UI only. Domain and session logic stay as they are. TDD where there is logic in `lib/`; component
tests are adapted to the new texts and structure. One commit per task.

## Decisions already made (user, 2026-10-25)

- Light theme only. Dark mode is removed (`color-scheme: light`, no `prefers-color-scheme` block).
- The kladblok keeps its 6 cells (2 × 3) and the short-screen row dropping (`SHORT_SCREENS`).
- Meetkunde stays in the list (8 rows), with its own glyph.
- The detail list is derived from `TOPIC_LABELS`: name before the first ` (`, detail inside the
  parentheses. No new copy. All sets except Tafels share one detail layout.

## Assumptions to confirm at review

1. The glyphs now come from the brief (multicolour inline SVGs, all 8 sets incl. Meetkunde).
   The brief calls the Meetkunde subtitle "Hoeken, omtrek, oppervlakte en inhoud" a placeholder; I keep
   the existing description ("Omtrek, oppervlakte, inhoud, hoeken en vormen"). The Meetkunde detail
   list is not designed; it uses the same layout, derived from `TOPIC_LABELS`.
   The brief contradicts itself: the acceptance list says yellow only in the logo and the Herhaling
   label and sky blue only on Tip/Uitleg and the active cell, but §1/§2 use `#FFD84D` (Start number),
   amber (glyphs) and blue (glyphs). I follow §1/§2 and treat the checklist line as outdated.
2. Progress bar fill = first attempts finished / total (a repeat leaves it unchanged).
3. Decided (user, 2026-10-25): generators mark the unknown explicitly with a `SLOT` marker
   (spec §8); a literal `?` is always a question mark. No text heuristics. Slot-less prompts
   (word problems, instructions) never change colour (brief §3.12).
4. Ja/Nee correct state (not in the brief): the chosen button turns green with ✓, the other is
   dimmed, plus the auto-advance bar.
5. The answer field keeps `tall` (6rem) for fraction kinds: an open template does not fit 64 px.
6. Prompt sizes (spec §3.3, §3.4): a prompt with a slot uses the length steps, question 38 / 28 /
   22 px and feedback 44 / 32 / 24 px; a prompt without a slot is question text, 22/30/700 in
   both states (brief §3.12); Ja/Nee 34/42. To be checked on a phone.
10. Units: the brief's §2 makes the suffix muted, §3.12 "same colour as the field text". Muted
    while typing, `--good-text` in the correct state. The feedback tiles and the result tiles
    show prefix and suffix (brief §3.12 for the panel; the result tiles follow for consistency).
7. Maskable and apple icons: keep `minimal2023` with the padded safe zone, filled with `#5B3FD1`
   (the brief wants a full-bleed gradient; the assets generator takes one source image, so the
   corners of the padding differ slightly from the gradient). Alternative: a second config.
8. The kladblok keypad keeps the existing labels; only the key order changes (below).
9. `#app` loses its padding: every screen sets its own side padding (16 px) and a bottom padding of
   `24px + env(safe-area-inset-bottom)`; the top gets `env(safe-area-inset-top)`.

## Task 6a — Slot marker in the generators (lib, TDD)

Files: `src/lib/slot.ts` (new), `src/lib/slot.test.ts`, every `src/lib/topics/*.ts` that writes a
`?` as the unknown (~29 files, incl. the `'?'` in `ratios.ts:109` and the fraction slots in
`fractionArithmetic.ts`), their tests, `src/lib/fractionText.ts` (+ test), a sweep test
`src/lib/topics/slot.sweep.test.ts` (new).

Domain change, presentation only: the prompt text changes, values, keys and checks do not.

- `slot.ts`:
  - `export const SLOT = '\u{E000}'` (private-use code point: never in real text, counts as one
    character in `promptSize`);
  - `hasSlot(prompt: string): boolean`;
  - `plain(prompt: string): string` replaces `SLOT` with `?` (for tests and anything that needs
    readable text).
- Generators write `${SLOT}` wherever the answer goes; word-problem question marks stay `?`.
  Tests that compare prompt strings compare `plain(prompt)` so they stay readable.
- `fractionText`: the fraction regex accepts `SLOT` instead of `?` as a numerator or denominator,
  and a `SLOT` outside a fraction becomes its own run (`{ kind: 'slot' }`). A literal `?` is
  plain text, also next to `/`.
- Question keys: unchanged where they are built from values; where a key embeds the prompt, use
  `plain` so a key never contains the marker.

| `slot.ts` / `fractionText` case | Expected |
|---|---|
| `hasSlot('7 × ' + SLOT + ' = 56')` | true |
| `hasSlot('Hoeveel busjes zijn er nodig?')` | false |
| `plain('3/4 = ' + SLOT + '/12')` | `3/4 = ?/12` |
| fractionText of `3/4 = SLOT/12` | fraction run with numerator slot, denominator `12` |
| fractionText of `7 × SLOT = 56` | text, slot, text |
| fractionText of `… nodig?` | one text run, no slot |

| Sweep (every generator in `TOPIC_GENERATORS`, 1000 seeds, every step) | Expected |
|---|---|
| slot count | at most 1 |
| literal `?` | only as the last character |
| prompt `= ?` or ` ? ` written literally | absent (caught by the rule above) |
| samples: `lcm`, `length` (`2 uur = ? min` form), `scale` (`… in het echt ? km`), `fractionArithmetic` (of-form `3/4 van 24 = ?`, equivalent `?/12`), `powersRoots` (`n = ?`) | `hasSlot` true |
| samples: ratio word problems, `angles` sentence form, `properties` rewrite step, `divisibility` | `hasSlot` false |

## Task 6b — Slot rendering in `MathText`
